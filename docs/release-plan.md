# GitHub 与后续自动化路径

## 首次发布的定位

建议仓库名：`industrial-ai-weekly-pipeline`。

描述：A human-reviewed industrial AI intelligence workflow with source validation, editorial rules, and document delivery.

当前包适合展示工作流设计和真实迭代。若直接分享，请保留 README 的快照状态与已知问题，不承诺克隆后即自动联网出稿。

此文档记录项目首次整理时的发布计划。远程发布应由维护者选择所有者与公开/私有，确认材料授权并决定许可证。原始聊天、公司内部资料和真实稿件不应因便于演示而直接提交；需要样刊时另行选取可公开且重新核验的材料。

## 三个迭代阶段

### 阶段 1：规则与代码一致

统一候选标题多样性、日期口径、字体槽位和显式文档结构；将规则版本与每次产物关联。清理旧要求，补充反例与回归测试。

### 阶段 2：运行可追溯

新增运行目录和 manifest，保存日期、来源 ID、核验依据、审核状态、文件摘要、耗时与版本。增加重复事件、链接、引用编号、内部备注和交付物齐全检查。来源事实的判定仍需原文与人工复核。

建议新增独立内部审核表，记录 event_date_basis、source_type、checked_at、review_status。保持现有公开 sources.csv 接口时，不要直接添加列破坏旧验证器；可用 source ID 建立旁表。

### 阶段 3：定时启动与人工批准

在稳定的单次执行器上接模型与搜索能力，再加入调度、断点、重试、运行日志和有意义的失败通知。仅在整期质量检查通过后进入人工审稿。发布连接作为独立能力，经授权后执行。

GitHub 保存代码和文档；把项目上传到 GitHub 本身不会自动拥有联网检索、模型调用或可靠调度。此包尚未实现上述执行器，也未提供假的定时运行工作流。

## 文件验收

生成 Word 后检查结构、内容、字体、分页与 PDF。保存重开在独立副本中做，分别记录 Microsoft Word、WPS、操作系统与版本，再做双向跨平台重开。未有原生验证环境时标为未实测，不能用 ZIP 检查、同库读回或第三方渲染替代。

核心文档离线可读、可编辑；外部信源链接访问和新一期检索需要网络。不要将这两种“离线可用”混淆。
