# 演进：把编辑反馈写成可复用标准

| 阶段 | 关键变化 | 意义 |
|---|---|---|
| 早期业务实践 | 先用 Skill 生成一周信源与正文并送审 | 验证 AI 辅助内容生产可进入真实流程 |
| 2026-08-11 整合 | 三个独立 Skill 合并为一次连续任务 | 统一搜集、写作、标题的衔接 |
| 交付约束 | 15 条升级为 25–30 条；加入发布时间/事件时间与 Word | 可检查的产物标准替代模糊的“写一篇” |
| 内容深化 | 从三两行摘要升级为事实、关键数字、意义与指向融合的长段落 | 改善信息密度与可读性 |
| 2026-08-12—14 编辑规则 | 主标题选最强新闻；章节表达共同变化；新闻标题体现新状态 | 建立三级标题的不同职责 |
| 科研写法 | 区分预印本、期刊/会议发表；避免每条机械交代日期与平台 | 同时控制事实边界与阅读节奏 |
| 换期复核 | 核验官网/IR 来源、日期与标题事件重复 | 检查跨次运行是否继承规则 |
| 2026-09 字体 QA | 中文字体验证、样式、渲染与逐页检查 | 将文档可用性纳入交付 |
| 2026-10 清稿 | 分离内部采集记录；统一英文参考文献；修订另存新版本 | 降低未清理备注进入正文的概率 |

此项目的可复用价值在于：用户把具体失败现象转化为规则，Agent 将规则落实到下一期。当前规则仍存在冲突，维护工作必须包括删除过时要求，而不只是不断追加文本。

## 三个原始模块

- `industrial-ai-report`：历史去重、五类定向检索、四列 CSV。
- `industrial-ai-writer`：基于 CSV 的动态章节、内参写法和 Markdown，原篇幅要求为约 3000–3500 字。
- `industrial-ai-headline-editor`：大主体、硬动作、数字和影响，原先允许同一新闻的八种变体。

合并后使用六列 CSV，加入日期/数量校验与 Word。之后的编辑反馈改变了长文标准、候选标题多样性及清稿要求。原始模块的部分旧规则仍残留，见 known-issues。

## 人与 AI 的分工

工作流维护者定义需求、编辑标准、验收与迭代；AI 承担检索、草拟、脚本与文件加工；业务审稿和排版发布保留人工协作。项目不主张由一人或 AI 独立完成全部业务。
